# 目的

Itadaki Atlas の機能要件を定義する。フェーズ1（MVP）の実装対象と完了条件の一次情報源。

## 1. フェーズ1のスコープ

**ご当地ラーメン約180種を、地図と索引で引ける状態にして英日2言語で公開する。**

含まないもの（意図的な除外）:

- 写真・イラスト（系統色アイコンで代用。`.doc/40_operation/01_strategy.md`）
- 詳細属性（麺・濃度・歴史・元祖店）— スキーマのみ用意
- 地域ページ（エリア軸）— フェーズ2
- アカウント・ログイン — フェーズ3
- コメント欄 — 当面設けない

## 2. 機能要件一覧

### F-01 地図表示

| 項目 | 内容 |
| :--- | :--- |
| 概要 | 掲載アイテムを日本地図上にピンで表示する |
| 詳細 | ・フルスクリーン地図を常に背景に置く<br>・ピンは**主系統ごとに色分け**（写真がないため、系統色がアイコンの役割を担う）<br>・全国俯瞰時は**ディフォルメ地図**（県グリッド）に切り替える<br>・ズームインで実座標地図（MapLibre）に遷移する |
| 完了条件 | スマホで約180件が地図表示され、ズームレベルに応じて2種類の地図が切り替わる |

### F-02 ボトムシート

| 項目 | 内容 |
| :--- | :--- |
| 概要 | 索引・詳細を下からのドラッグ可能シートに載せ、**ページ遷移なしで地図⇔詳細を往復**できる |
| 詳細 | ・3段階スナップ: ピーク / ハーフ / フル<br>・ピンタップ → ピーク位置でアイテムカード表示 → 引き上げで詳細へ |
| 完了条件 | 3段階のスナップが動作し、ピンタップから詳細まで遷移なしで到達できる |

### F-03 索引

| 項目 | 内容 |
| :--- | :--- |
| 概要 | 地図と**対等なビュー**として、同一データソースから生成する |
| 詳細 | 3軸で引ける: **五十音／アルファベット順・地域別・系統別** |
| 完了条件 | 3軸すべてで全件が引ける。地図を使わずに全アイテムに到達できる |

索引は**スクリーンリーダー向けの主要動線**でもある（F-07）。「地図の付属品」ではなく、地図と同じ情報に到達できる独立した経路として実装する。

### F-04 アイテム詳細

| 項目 | 内容 |
| :--- | :--- |
| 概要 | 個別アイテムのページ（`/[genre]/[slug]`） |
| 表示項目 | 名称（**日本語名 — ローマ字 — 英訳**の三点セット）／発祥地／主系統／一言説明／出典 |
| 完了条件 | 全件で三点セット表記と出典が表示される |

英訳は直訳でなく**説明訳**とする（`せせり → Seseri — chicken neck meat`）。これが無いとミッション②（メニュー解読）が成立しない。

### F-05 言語切り替え（英日）

| 項目 | 内容 |
| :--- | :--- |
| 概要 | 英日を切り替える。方式は Platform `../.doc/10_system/10_growth_infra.md` §3 に従う（差分なし） |
| 対象言語 | `ja` / `en`。詳細は `.doc/10_system/10_growth_infra.md` §2.1 |
| 完了条件 | 全ページで英日が切り替わり、`hreflang` が正しく出力される |

### F-06 事業者問い合わせフォーム

| 項目 | 内容 |
| :--- | :--- |
| 概要 | 「掲載・広告についてのお問い合わせ」ページ。**待ちの営業の受け皿** |
| 詳細 | ・実装はフォーム + メール通知のみ（管理画面は作らない）<br>・**日本語表示時のみ表示**する（出稿者はほぼ国内のため）<br>・英語版はフッターに `For business inquiries` のメールリンク1行のみ |
| 完了条件 | 送信内容がメールで届く。日本語版のみに表示される |

フェーズ1から設置する理由は、店舗・自治体からのインバウンドリードを**初期から取りこぼさない**ため。

### F-07 アクセシビリティ

| 項目 | 内容 |
| :--- | :--- |
| 目標 | **WCAG 2.2 AA 相当** |
| 詳細 | ・索引を、地図と同等の情報に到達できる代替手段として提供する<br>・地図ピンは `button` 要素とし、キーボードでフォーカスできる<br>・詳細パネルの開閉時にフォーカスを管理する |
| 完了条件 | Lighthouse の a11y スコア 90+ |

### F-08 SEO

| 項目 | 内容 |
| :--- | :--- |
| 詳細 | メタタグ／OGP／`sitemap.xml`／`hreflang`／構造化データ |
| 完了条件 | 全ページにメタ・OGPが出力され、sitemap が生成される |

OGPは**画像カードを自動生成**する（三点セット・系統色のタイポグラフィのみ）。写真を持たないサイトの、共有時の唯一の「画像」。

### F-09 回遊（つながり）

| 項目 | 内容 |
| :--- | :--- |
| 概要 | **行き止まり禁止。** 詳細ページから「名前のついた関係」で次のアイテムへ進める |
| 詳細 | ・`food_item_relations` 1行が**両端の詳細に双方向で**リンクを生む（源流⇄派生・対比）<br>・リンクには相手の説明文を添え、**押す前に一つ学べる**形にする<br>・同じ県の他アイテムはデータ不要で自動リンク<br>・関係も事実の記述として扱う。「派生」は裏の取れるもののみ。「対比」は事実主張でない編集上の並置 |
| 完了条件 | 関係1行で両側にリンクが出る。E2Eで双方向を検証 |

回遊は成長モデルの中核実体（`.doc/00_concept/02_vision.md` §4）であり、フェーズ2送りにしない。

### F-10 ジャンルページ（`/[genre]`）

| 項目 | 内容 |
| :--- | :--- |
| 概要 | "types of ramen" 系クエリを受けるSEO正面。**genres に行を足すだけで生える** |
| 詳細 | ・系統別の一覧（系統を持つジャンルのみ）<br>・**図鑑セクション**: 発祥地を持たないアイテム（部位等）が入ると自動で現れる<br>・地域チップ（その ジャンルのデータがある県だけ並ぶ） |
| 完了条件 | 2ジャンル目がコード変更なしで表示される |

### F-11 地域ページ（`/region/[pref]`）

| 項目 | 内容 |
| :--- | :--- |
| 概要 | "what to eat in ..." 系クエリを受ける第二のSEO正面。**ジャンル横断**でその県のアイテムが並ぶ（「広くする」方向の実体） |
| 詳細 | データが1件でも入った県だけページが生える。**0件の県は404**（薄いページを量産するとSEOに毒） |
| 完了条件 | データ追加だけで県ページが増える |

## 4. 非機能要件

| 項目 | 要件 |
| :--- | :--- |
| 対応デバイス | **スマホファースト。** PC は後回しにせず対応するが、設計の起点はスマホ |
| パフォーマンス | Lighthouse a11y 90+（F-07）。地図の初期表示を阻害しないこと |
| 対応言語 | `ja` / `en`（フェーズ1） |
| 認証 | **なし**（`.doc/10_system/01_architecture.md` §3） |
