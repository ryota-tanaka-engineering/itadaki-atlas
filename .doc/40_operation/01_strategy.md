# 目的

Itadaki Atlas のコンテンツ運用ルール（出典・執筆・イラスト・フィードバック収集）を定義する。品質と中立性を、属人的な良識ではなく**運用ルール**として担保する。

## 1. 出典と執筆の規律

North Star の「正確さ > 網羅性 > 速度」を運用に落としたもの（`.doc/00_concept/01_north_star.md` §2）。

### 1.1 出典

- 全アイテムに**出典を1件以上**紐付ける（`food_item_sources`）。記事末尾に参考文献として自動表示する
- ジャンル共通の出典は `genres.default_source` で一括適用してよい
- 出典には `accessed_at`（参照日）を必ず記録する

### 1.2 転載の全面禁止

| 対象 | ルール |
| :--- | :--- |
| **文章** | **参照するのは事実のみ。文章表現は必ず書き直す。** 出典の言い回しをなぞらない |
| **画像** | 他サイトからの転載を**全面禁止**。例外を設けない |

法人運営であり、営業で事業者・自治体に対峙する以上、権利関係の瑕疵は事業そのものを止める。**「バレなければよい」の判断を一切しない。**

### 1.3 不確かな情報の扱い

発祥に諸説あるものは、**断定せず「諸説ある」と書いて併記する**。断定して権威的に見せない（`.doc/00_concept/05_brand.md` §4.1）。

## 2. イラスト運用（フェーズ2以降）

### 2.1 方針

**統一イラストを主軸とする。** AI生成を可とするが、以下を必須工程とする。

| # | 必須工程 | 内容 |
| :--- | :--- | :--- |
| **①** | **実物特徴との照合レビュー** | 生成物が実物の特徴と合致しているかを人間が確認する。原材料が判別できる具体性を維持し、**デフォルメしすぎない** |
| **②** | **生成ツールの商用規約確認** | 使用するツールの商用利用条件を確認・記録する |
| **③** | **イラストである旨の明示** | 写真と誤認させない |

### 2.2 スタイル確定プロセス

量産前に必ず実施する（詳細は `.doc/99_management/01_roadmap.md` §5）。

- 描き分け難易度の高い5〜10種でストレステスト
- **合否ライン: 茶系スープ同士が区別できること**
- 合格したスタイル定義をプロンプトテンプレ + 参照画像としてスキル化してから量産

### 2.3 実写への差し替え

収益化後、タイアップ提供または**出稿商材としての販売**により実写へ差し替える。画像権利問題とマネタイズを同時に解決する構造として設計している（`.doc/00_concept/04_strategy.md` §1.3）。

## 3. 広告・スポンサー枠の運用（フェーズ3）

中立性は**商品価値の一部**であり、運用で守る。

| ルール | 内容 |
| :--- | :--- |
| 枠数 | 各アイテムページ**最上部の1枠限定** |
| 表示 | **「PR」表記を必須**（ステマ規制対応） |
| 分離 | イラスト解説の中立性は維持する。**元祖店の編集掲載とは別枠**として扱う |
| 期限管理 | `shops.sponsored_until` で掲載期限を管理し、期限切れは自動的に非表示にする |

編集（元祖店 = `role: originator`）と広告（`role: sponsored`）をデータ上で分離しているのは、運用者が混同できないようにするため。

## 4. フィードバック収集

### 4.1 コメント欄は設けない

| 理由 | 内容 |
| :--- | :--- |
| 過疎感 | 初期にコメントが付かない状態は、むしろ信頼を損なう |
| 多言語モデレーションコスト | 英日（将来は中韓）のモデレーションは少人数運用で負担が大きい |
| シグナル純度 | 有用な指摘がノイズに埋もれる |

**交流はSNS（X / Instagram / TikTok / YouTube）側で起こし、サイトは静かな参照先に保つ。**

再検討の条件: トラフィックとコミュニティが育ち、必要性が実証されたとき。

### 4.2 収集手段

| 手段 | フェーズ | 内容 |
| :--- | :--- | :--- |
| **事業者問い合わせフォーム** | **1** | 「掲載・広告についてのお問い合わせ」。実装はフォーム + メール通知のみ。**待ちの営業の受け皿**として初期から設置する |
| 記事末尾の非公開フィードバックフォーム | 2 | 「役に立った?」の選択式 + 「足りない情報」の任意自由記述。**公開しない**のでノイズにならない |
| **未掲載ご当地グルメ投稿フォーム** | 2 | 地元民の「うちの町の○○が載ってない」を収集し、DB成長の燃料にする。採用時は**「情報提供: ○○さん」とクレジット表示**して投稿インセンティブ化する |

### 4.3 問い合わせフォームの言語非対称

- **日本語表示時のみフォームを出す**（出稿者はほぼ国内のため）
- 英語版はフッターに `For business inquiries` のメールリンク1行のみを残し、海外レストラン・メディアからの想定外リードを拾う

## 5. 公開ワークフロー

1. `status = draft` で投入する
2. 出典が紐付いているか、三点セット表記（日本語名 — ローマ字 — 英訳）が揃っているかを確認する
3. `status = published` へ変更する

**出典なし・三点セット欠けのまま公開しない。** この2点はデータ投入時のバリデーション対象とする（`.doc/20_data/01_models.md` §7.3.3）。
