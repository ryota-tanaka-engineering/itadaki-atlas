# 目的

Itadaki Atlas の計測設計を定義する。KGI/KPI を実際に測れる形に落とし、**虚栄の指標を採らない**ことを担保する（`../.doc/documentation_rules.md` §6C-3）。

## 1. 計測の原則

### 1.1 PVを頂点に置かない

KGI は **既存事業への送客数**であり、トラフィックは中間指標に留める。PVを最上位に置くとバズ狙い・薄い量産へ判断が歪み、North Star と衝突するため（`.doc/00_concept/01_north_star.md` §3）。

### 1.2 Actionable であること

「増えた/減った」だけで終わる指標を置かない。**次の打ち手が決まる指標**のみを採る。

| ✅ Actionable | ❌ 虚栄の指標 |
| :--- | :--- |
| 地図操作率（低ければUXを直す） | 累計PV |
| ジャンル横断回遊率（低ければリレーションを増やす） | SNSインプレッション総数 |
| 送客CV（低ければ導線を直す） | 総ページ数 |

### 1.3 フェーズ1は認証を持たない

ユーザー単位の追跡は行わない。**GAのページトラッキングで足りる**範囲に計測を留める（`.doc/10_system/01_architecture.md` §4）。

## 3. カスタムイベント定義（フェーズ1）

GAの標準ページビューに加えて計測するもの。**これ以外を安易に増やさない。**

| イベント名 | 発火タイミング | 何を判断するか |
| :--- | :--- | :--- |
| `map_pin_tap` | 地図のピンをタップ | 地図が実際に使われているか |
| `sheet_expand` | ボトムシートをハーフ/フルへ展開 | **地図操作率（フェーズ1の主要KPI）** |
| `index_view` | 索引ビューを開いた | 地図と索引のどちらが主動線か |
| `index_axis_change` | 索引の軸を切り替え（五十音/地域/系統） | どの軸が使われているか。使われない軸は削る判断材料 |
| `locale_switch` | 言語を手動切り替え | 言語誘導が適切か |
| `map_style_switch` | ディフォルメ地図⇔実座標地図の切替 | 切替のズーム閾値が適切か |
| `contact_form_submit` | 事業者問い合わせフォーム送信 | 待ちの営業の受け皿が機能しているか |

## 4. フェーズ別の計測対象

| フェーズ | 主要KPI | 対応する計測 |
| :--- | :--- | :--- |
| **1** | 公開アイテム数 / GSCインデックス数 / オーガニック流入 / **地図操作率** / SNSフォロワー | GSC + GA + `sheet_expand` |
| **2** | ジャンル横断回遊率 / フォーム件数 / 地域ページ流入 | GA（遷移経路）+ フォーム送信数 |
| **3** | アカウント登録数 / 制覇マップ利用率 / **送客CV** / タイアップ成約 | 認証解禁後にユーザー単位計測を追加 |

### 地図操作率の定義

```
地図操作率 = sheet_expand の発生セッション数 / 地図ページのセッション数
```

これが低い場合、「地図は見られているが使われていない」ことを意味し、**フルスクリーン地図 + ボトムシートという設計そのものの検証結果**になる。フェーズ1で最も重要な指標。
