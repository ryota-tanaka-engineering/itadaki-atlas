# 部隊指示書: ラーメン全件に4章目「どう食べるのか」と麺・濃さの属性を書く（全文を読んでから着手）

出力は scratchpad のみ。リポジトリは読み取り専用（`data/` の既存ファイルで形式と文体を参照可）。再委譲禁止。Web には出られない前提（本環境は外部サイトへ到達できない）。5件書くごとに出力ファイルへ途中保存する。

## 目的

Itadaki Atlas（日本食の地理データベース。主対象は海外の読者。KGI は送客。「土地と食の因果」を語る媒体。ランキング・煽り禁止）の詳細ページは、現在「何でできているか／どう作るのか／なぜこの形になったのか」の3章で**正体**を説明している。ユーザーの決定（2026-10-04「詳細の方に情報を厚くすべき」）を受け、**読者が店で実際にどう頼み、どう食べるか**を4章目「どう食べるのか」として足し、あわせて麺の太さ・縮れ・濃さをフィルタ用の構造化属性として入れる。

North Star は「浅い興味の人を『食べてみたい』へ一歩動かす」こと。4章目は読み物ではなく、**店の前で役に立つ段落**として書く。

## 入力

- 担当アイテム: `{{input}}`（JSON 配列。各要素に slug / name_ja / name_romaji / name_en / pref / city / style（主系統）/ summary_ja / summary_en / body_ja / body_en / tags）。**既存の本文（3章）は変更対象ではない。読んで、矛盾しない4章目を書く**
- 文体見本（札幌ラーメンの既存章、常体・感覚描写から入る）:
  > 味噌のコクとにんにくの香りが最初に来て、そのあとに挽肉と炒め野菜の甘みが追いかけてくる。表面を覆うラードが湯気を閉じ込めるので、丼は最後まで熱いまま。

## 各アイテムに書くもの（出力 JSON の items[]）

| キー | 内容 |
| :--- | :--- |
| `slug` | 入力と同じ |
| `howto_ja` | 4章目の本文のみ（**見出し `## どう食べるのか` は書かない**。投入時に機械で付く）。150〜250字。段落は1〜2つ（空行で区切る）。Markdown は `**強調**` のみ可 |
| `howto_en` | 同内容の自然な英語（直訳しない）。見出し `## How to eat it` は書かない。80〜160 words |
| `noodle_thickness` | 麺の太さ。語彙: `極細` / `細` / `中細` / `中太` / `太` / `極太` のいずれか。既存本文・概要から読み取れないときは `null` |
| `noodle_curl` | 麺の形。語彙: `ストレート` / `ちぢれ` / `手もみ` のいずれか。読み取れないときは `null` |
| `richness` | 濃さ。1〜5 の整数。ラーメン全体の中での相対尺度（定義は下記）。判断できないときは `null` |
| `notes` | 任意。裏が取れず書けなかったこと・要判断 |

### 濃さ（richness）の定義（10人が見て同じ値になるよう、スープの実体で決める）

| 値 | 実体 |
| :--- | :--- |
| 1 | 澄んだ清湯で脂がほとんど浮かない（鶏・煮干・昆布の淡い塩／醤油。冷やし系もここ） |
| 2 | 清湯だが脂や香味油が少し浮く（多くの醤油・塩の清湯） |
| 3 | 清湯に背脂やラードがしっかり乗る、または軽めの豚骨醤油・白湯 |
| 4 | 乳化した豚骨・鶏白湯、味噌にラードを重ねる型など、口に膜が残る |
| 5 | 濃厚な乳化スープに背脂・ラードを重ねる、またはつけ汁級の粘度 |

## 4章目に書くこと（店の前で役に立つことだけ）

1. **頼み方**: その型で普通にある選択（麺の硬さ・味の濃さ・脂の量の指定、替え玉、大盛、ライス、スープ割り、つけ麺の温／冷 など）。**その型に固有の習慣だけ**を書く。全ラーメン共通の一般論（券売機の使い方・麺のすすり方）は書かない（別のガイドが受け持つ）
2. **卓上の薬味・調味料**: その型でよく置かれるもの（紅生姜・辛子高菜・ごま・胡椒・にんにく・酢・一味・ラー油など）と、入れる順や目安。店によることを必ず断る
3. **食べる順・コツ**: 既存本文から読める特徴に基づく（ラードの膜で熱いので最初は少しずつ／極細麺は伸びやすいので早めに／具を先に崩すと味が変わる／途中で薬味を足して味を変える 等）
4. **場面・時間**: 朝ラー・〆の一杯・夏限定・家庭／店どちらで食べる型か、など、その型に意味のあるものだけ

## 編集規律

- **既存本文・概要・系統・タグから読めること**と、**その系統（醤油／味噌／塩／豚骨／その他）の一般的な作法**の範囲で書く。確信の持てない固有の作法（「この町では必ず〜」）は書かない。Web で裏が取れない環境なので、創作しないことを最優先にする
- 文体は「〜ことが多い」「店による」「〜とされる」。断定しない。店名・チェーン名・値段・営業時間は書かない
- 格付け語（三大・一番・No.1・ランキング・受賞・認定・人気）を書かない。優劣を言わない
- 既存3章と重複する説明（材料・製法・由来）を繰り返さない。4章目は「頼む・食べる」だけ
- ja と en は各言語で書く（直訳しない）。en では日本語の語を初出でローマ字＋短い説明にする（kaedama — a refill of noodles）
- 麺の属性は「既存本文・概要に書いてあること」から取る。本文が「中太のちぢれ麺」なら `中太` / `ちぢれ`。「細麺」だけなら `細` / `null`。書いていなければ `null`（推測で埋めない）

## 自己検証してから報告

- 担当 slug が全件ある（欠けなし・重複なし）
- `howto_ja` 150〜250字、`howto_en` 80〜160 words、見出し行（`## `）を含まない
- 語彙（麺の太さ・形）が上記の値か null、richness が 1〜5 の整数か null
- 格付け語・店名・値段が無い。既存3章と矛盾しない（麺の属性は本文の記述と一致）
- 報告: 件数／null にした属性の件数と理由／要判断
