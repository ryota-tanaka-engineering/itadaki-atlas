## 各アイテムに必要な項目（束 JSON の items[]）
- slug（英小文字とハイフン。ご当地ものは `<地名>-<種類>`、型・品種・部位は素の名。既存と衝突させない）
- name_ja / name_romaji / name_en（説明訳。例 "Masu-zushi — pressed trout sushi wrapped in bamboo leaves"）
- type（dish / ingredient）、shelf、genre
- origin_pref / origin_city / lat / lng（発祥地・産地。都道府県は正式表記「東京都」「京都府」。lat/lng は代表地点の小数4桁。土地が特定できない型・全国区は空欄＝図鑑枠）
- summary_ja（80〜160字・断定しない）/ summary_en（同内容の自然な英語）
- body_ja / body_en: 3章固定。見出しは一字一句「## 何でできているか」「## どう作るのか」「## なぜこの形になったのか」／「## What it's made of」「## How it's made」「## Why it took this shape」。ja 各章150〜250字（計500〜750字）。en は同内容の自然な英語（直訳不要）
- sources: 1〜3本 `{title,url,publisher,accessed_at}`。`curl -sI` で200確認した URL のみ。Wikipedia は最終手段（概要の出典が Wikipedia なら本文執筆時に一次資料へ差し替えを試みる）
- regions: 土地との結びつき。`relation_type` は「名産地」「本場」（発祥は origin から自動生成されるので書かない）。本場＝どこでも食べられるがここのは特別。**本場は note_ja/note_en に構造的理由の一文と source_url が必須**。受け皿アイテムには本場を2箇所以上
- relations: 他アイテムへの名前つき関係を最低1本（行き止まり禁止）。語彙: 源流 / 派生 / 兄弟 / 対比 / 使用食材（料理→食材）/ 代表ネタ（料理→代表素材）。**向き**: 「A → B 派生」= A は B から派生（子→親で書く）、「A → B 源流」= A は B の源流（親→子）。to_slug は既存 slug か同じ出力内の新 slug。源流・派生は出典で裏が取れるものだけ、取れなければ対比
- tags: 既存語彙のみ、客観的に付くものだけ: {{data/tags.json の slug 一覧を転記}}

### 文体見本（札幌ラーメン ja・抜粋）
## 何でできているか
味噌のコクとにんにくの香りが最初に来て、そのあとに挽肉と炒め野菜の甘みが追いかけてくる。表面を覆うラードが湯気を閉じ込めるので、丼は最後まで熱いまま。多加水の黄色い中太ちぢれ麺は濃いスープをよく持ち上げ、噛むと弾力が残る。
## なぜこの形になったのか
一説によると、はじまりは味噌汁に麺を入れた賄いだったという。真冬の平均気温が氷点下になる街では、丼は食べ終わる前に冷める。表面のラード、炒めて香りを立てた味噌、太くて熱を抱える麺——この一杯の特徴はどれも、寒さへの答えとして読める。
