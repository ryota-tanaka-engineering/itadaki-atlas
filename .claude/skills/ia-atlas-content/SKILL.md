# Itadaki Atlas コンテンツ制作・投入

## 編集規律（1件でも破ると差し戻し）

1. **全アイテムに出典必須**（URL実在確認。自治体・観光協会・組合・発祥店公式 > 大手メディア > Wikipedia最終手段）。**出典はDB内部の検証データであり、ページには表示しない**（誤情報・リンク切れの露出リスク回避。UIは「訂正を送る」のみ）
2. **文章は書き下ろし**（転載禁止）。日英とも直訳でなく各言語で書く
3. **三点セット**: name_ja・name_romaji・name_en（説明訳。固有名詞の転写を name_en にしない）
4. **ランキング・優劣表現禁止**。企業単一ブランドは原則対象外。保護対象・規制種は不掲載
5. 正確さ > 網羅性 > 速度

## 情報構造（2026-08 確定版）

- **タグ一元 + 排他棚1本**: 棚28本（料理10・食材9・仕込み9）は全アイテム必須・1つだけ。URL・地図記号・数え上げの単位
- **ジャンル昇格制**: 同型20件以上+実在の呼び名（造語禁止）で棚内「その他」から昇格。データ移動のみで昇格できる
- **回遊は関係が主役**: 源流/派生・兄弟・対比・使う⇄使われる の4語彙。公開条件=関係・名産地・同県のいずれか1つ以上（行き止まり禁止）
- 3群記号: ●料理（生まれた）/ ■食材（育てる）/ ◆仕込み（仕込む）
- 全体像・検証ログはインベントリ資料（Artifact「日本の食・全域インベントリ」）と scratchpad ではなく `.doc` 反映後はそちらが正

## Tier制（深さの段階・均一を約束しない）

| Tier | 内容 | 対象 |
| :--- | :--- | :--- |
| 1 図鑑カード | 三点セット・座標・要約・解剖タグ | 全アイテム（標準） |
| 2 物語つき | +章2〜3本（章立てMarkdown） | 検索需要・話題性の高いもの |
| 3 旗艦 | 全章+解剖断面図（ジャンル型のパラメトリックSVG） | 各ジャンルの看板数件 |

章立ては可変（章の有無・長さ自由）。解剖図はジャンルごとに型を1点作り、アイテム側はパラメータ差し替え。

## 投入手順

```bash
cd itadaki-atlas
bash -c 'set -a; source .env.local; set +a
npx tsx scripts/import-genres.ts --file data/genres.csv
npx tsx scripts/import-food-items.ts --file data/<genre>.csv --genre <genre-slug> --dry-run  # 三点セット全列を目視
npx tsx scripts/import-food-items.ts --file data/<genre>.csv --genre <genre-slug> --publish'
```

- CSV生成は**pythonのcsvモジュール必須**（name_en にカンマが入る。手書き処理で全行破損した事故あり）
- **slugはグローバル一意**。地名だけのslugはジャンル間で衝突する（博多うどんが博多ラーメンを上書きした事故あり）→ 新ジャンルは `<地名>-<ジャンル>` 形式（例: `hakata-udon`）にし、投入前に既存slugと突合する
- 投入後: 対象ページの生成確認 → `npm run test:e2e` 全件。「掲載なし県」前提のテスト（現在=石川）はデータで埋まったら更新する

## 調査部隊への委譲

量産は `research-fleet`（グローバルSkill）の体制で回す。指示書には本Skillの「編集規律」「slug規則」「CSV規則」を全文転記すること（部隊は会話文脈を持たない）。
